# M-A4 — v0.1.0 tag Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cut the first public zero-line release. Tag `v0.1.0` on `main`, let M-A3's release workflow produce GitHub Release + npm-published `@zl/core@0.1.0` + updated Homebrew tap formula, then verify end-to-end that a fresh macOS user can install and run the quickstart.

**Architecture:** Almost no code change in this milestone — it's verification + orchestration. Four phases: (1) pre-flight (confirm M-A1/M-A2/M-A3 green and in place), (2) CHANGELOG cutover (rename `[Unreleased]` → `[0.1.0]`, seed a fresh `[Unreleased]`), (3) tag + release (push the annotated tag, monitor the release workflow through completion), (4) post-release verification (install from Homebrew on a clean machine, run the quickstart, smoke-test npm consumption). Any rough edges found during the dogfood pass are filed as Linear tickets under a v0.1.1 patch — they do NOT gate the v0.1.0 tag once the workflow completes successfully.

**Tech Stack:** git, GitHub Actions (release workflow built in M-A3), npm registry, Homebrew, Bun runtime, `gh` CLI.

**Related spec:** `docs/superpowers/specs/2026-04-16-zero-line-roadmap-design.md` (section "M-A — Foundation" → subsection "Exit criteria — M-A").

**Linear ticket(s):** M-A4 is a small milestone — 1 ticket per task, all attached to the `zero-line MVP → M-A Foundation` Linear milestone. Ticket IDs filed at execution time.

**Depends on:**
- **M-A1 merged** — `@zl/core@0.1.0` public API frozen (ZER-116), PluginStep/ResolvedStep types stable, PreflightCheck / StepError / ShellService / subcommands all in.
- **M-A2 merged** — `zl init` / `zl doctor` / `zl secret` all shipped; `ConfigService.secret` falls back to the OS keychain; README quickstart updated.
- **M-A3 merged** — CI workflow, release workflow (multi-arch build, GitHub Release, npm publish, Homebrew formula update), `CHANGELOG.md` seeded at repo root, `swissonid/homebrew-tap` repo exists, E2E integration test present.

Do **not** begin this plan until all three of the above are marked Done in Linear and green on `main`.

## Task 2: CHANGELOG cutover

**Files:**
- Modify: `CHANGELOG.md`

**Principle:** The release tag, the CHANGELOG cutover, and the version references in the README must land in a single commit so `git show v0.1.0^{commit}` tells the whole story.

- [ ] **Step 1: Decide the release date**

Use today's UTC date in ISO form. Example: `2026-04-20`. Capture as `$RELEASE_DATE`:

```bash
RELEASE_DATE=$(date -u +%Y-%m-%d)
echo "$RELEASE_DATE"
```

- [ ] **Step 2: Rename `[Unreleased]` → `[0.1.0] - $RELEASE_DATE` and seed new `[Unreleased]`**

Edit `CHANGELOG.md` so the top of the file reads:

```markdown
# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

## [0.1.0] - 2026-04-20

### Added
- Step contract (`defineStep` / `defineEffectStep`) with name scoping, options schemas, declared requirements, and subcommand registration.
- Pipeline engine with pre-flight requirement verification and structured `StepError` surfacing.
- `ShellService` port + `LocalShell` adapter with cancellation (SIGTERM → SIGKILL) and timeouts.
- `@zl/cli` — `zl run`, `zl list`, `zl init`, `zl doctor`, `zl secret set|get|list|delete`, `zl --help`.
- `@zl/step-hello` — reference step.
- OS-keychain-backed `SecretStore` (macOS); `ctx.config.secret(key)` falls back to the keychain.
- Homebrew distribution (`brew install swissonid/tap/zl`).
- CI + release workflow: typecheck, lint, tests on PRs; tag-triggered multi-arch binaries + npm publish + Homebrew formula update.

### Notes
- `@zl/core@0.1.0` is the first stable public API. Breaking changes go in `@zl/core@2.0` post-v1.
- Linux keychain support is stubbed; planned before v1.0.
```

Replace the date placeholder with the actual `$RELEASE_DATE`. Preserve any existing `### Added / Changed / Fixed` bullets under the old `[Unreleased]`; only the *header* is renamed.

## Task 3: Cut the `v0.1.0` tag

**Files:** none.

- [ ] **Step 1: Confirm `main` is at the CHANGELOG cutover commit**

```bash
git checkout main && git pull --ff-only origin main
git log --oneline -1
grep -q '^## \[0\.1\.0\]' CHANGELOG.md && echo "✓ CHANGELOG ready" || echo "✗ CHANGELOG mismatch"
```

Expected: "✓ CHANGELOG ready". If not, abort — Task 2 didn't land.

- [ ] **Step 2: Create the annotated tag**

```bash
git tag -a v0.1.0 -m "zero-line v0.1.0 — first public release"
```

(Annotated tag, not a lightweight tag; the release workflow reads the tag message into the GitHub Release body title.)

- [ ] **Step 3: Push the tag**

```bash
git push origin v0.1.0
```

- [ ] **Step 4: Monitor the release workflow**

Open `https://github.com/swissonid/zero-line/actions` in the browser, or:

```bash
gh run list --workflow=release.yml --limit 1
gh run watch --exit-status $(gh run list --workflow=release.yml --limit 1 --json databaseId -q '.[0].databaseId')
```

Expected: all matrix jobs (`darwin-arm64`, `darwin-x64`, `linux-x64`) green, the `publish-npm` and `update-tap` jobs green.

Timeout: if the workflow hasn't completed in 30 minutes, investigate. Likely suspects: npm auth (`NPM_TOKEN` secret), keychain on the macOS runner, Homebrew tap PAT (`TAP_GITHUB_TOKEN` secret).

- [ ] **Step 5: If the workflow fails**

Do NOT force-delete and re-push the tag. Instead:
1. Diagnose (read the failing job's logs).
2. Open a hotfix ticket for the underlying issue.
3. Fix on `main` (CI green).
4. Cut a new patch: `git tag -a v0.1.1 -m "..."`, push — the release workflow is idempotent per tag.

The `v0.1.0` tag stays in place as the historical first-attempt marker. A deleted-and-retagged `v0.1.0` confuses Homebrew cache invalidation and npm version immutability later.


Expected: all three return `0.1.0`.

(If only `@zl/core` is meant to be published at 0.1.0 per M-A3's decision, adjust this expectation — but whatever the policy is, the installed versions must match the tag. Mismatched plugin versions at the freeze point will haunt M-B.)

- [ ] **Step 3: Verify the Homebrew formula update**

```bash
gh api repos/swissonid/homebrew-tap/contents/Formula/zl.rb --jq .content | base64 -d
```

Expected: the formula's `url` points to a `v0.1.0` asset and the `sha256` lines match the `SHA256SUMS` file from Step 1. If they don't match, the formula is broken — open a hotfix ticket and investigate the `update-tap` job.

- [ ] **Step 4: Verify SHA-256 consistency**

```bash
# Download the SHA256SUMS file and each binary, then compare.
TMPDIR=$(mktemp -d) && cd "$TMPDIR"
gh release download v0.1.0 -R swissonid/zero-line
cat SHA256SUMS
shasum -a 256 zl-darwin-* zl-linux-* | diff - <(grep -E 'zl-(darwin|linux)' SHA256SUMS | awk '{print $1"  "$2}')
```

Expected: empty diff. If not, the release workflow's shasum step has a bug — hotfix.

## Task 5: Dogfood — fresh-machine quickstart

**Files:** none.

Perform this on a genuinely clean macOS environment — a spare machine, a fresh VM, or at minimum a throwaway user account that has never had `zl` installed. Do NOT use the dev machine; caching makes the test lie.

- [ ] **Step 1: Install via Homebrew**

```bash
brew tap swissonid/tap
brew install zl
zl --version   # expected: 0.1.0
```

If `brew install` fails, the formula / bottle is broken. Stop and fix; re-run the release workflow.

- [ ] **Step 2: Run the quickstart**

```bash
mkdir -p /tmp/zl-smoke-$$ && cd /tmp/zl-smoke-$$
zl init
# scripted answers: name="Smoke", bundleId=<default>, platforms=<default>
zl doctor
# expected: all checks ok (or warn — zero fails on a modestly-equipped macOS).
zl run ci
# expected: hello step runs, exit 0.
```

- [ ] **Step 3: Exercise `zl secret`**

```bash
zl secret set SMOKE_KEY  # prompt for value: "smoke-value"
zl secret get SMOKE_KEY  # expect "smoke-value"
zl secret list | grep SMOKE_KEY
zl secret delete SMOKE_KEY
zl secret get SMOKE_KEY  # expect exit 1, "Not found: ..."
```

- [ ] **Step 4: Verify npm consumption**

```bash
cd /tmp && mkdir zl-npm-$$ && cd zl-npm-$$
bun init -y
bun add @zl/core@0.1.0
bun -e 'import("@zl/core").then(m => console.log(Object.keys(m).slice(0, 5)))'
```

Expected: prints a non-empty list of exports (e.g. `["defineStep", "defineEffectStep", "StepError", ...]`). If import fails, npm publish is broken despite the earlier checks.

- [ ] **Step 5: Record findings**

For every rough edge encountered (confusing error message, missing doc link, silent failure, etc.), file a Linear ticket against the `M-B iOS Archive` milestone labelled `v0.1.x-hotfix`. These are NOT blockers for declaring v0.1.0 shipped — v0.1.1 will fold them in.
